## 2. 影片描述（≤300 字）

跟 AI 講了一大串需求，做出來的成品卻總是差一截？問題不在提示詞不夠長，
而是需求本來就有「你講不出口」的部分。

這一集把 RDQ 需求探索四象限法一次講清楚，並附上可直接安裝的技能：

- **四個象限**：你知道你知道的、你知道你不知道的、你不知道你知道的、
  你不知道你不知道的。人類只講得出前兩個，第三、第四要靠 Agent 訪談挖出來。
- **RDQ Skill 實演**：一句「用 RDQ 問我」，AI 最多問三輪，
  最後產出一頁草案規格卡，確認後才開工。
- **隱藏彩蛋**：ChatGPT Site 已內建 Cloudflare D1 / R2 後端資料庫，
  一行提示詞就能開啟，不用再接 Firebase 或 Supabase。

這是 AI Agent 基本功系列的最後一集，也是做 AI 專案的最後一塊拼圖。
技能網址放在說明欄，記得訂閱與分享，留言告訴我你最常漏掉哪一個象限。

## 3. 社群貼文（禁 Emoji）

### Facebook

跟 AI 說了一長串需求，做出來卻總是差一截。

我一直以為是提示詞不夠完整。後來發現不是，是需求本身就有講不出口的部分。

有些細節你太熟了，熟到你不覺得需要講。有些風險你根本不知道自己不知道。
這兩塊在專案裡往往最致命，卻永遠不會出現在你的提示詞裡。

這一集我整理了需求探索四象限法，並做成一個技能。動工前先讓 Agent 訪談你，
最多問三輪，最後給你一頁規格卡，確認過才開始做。

做完那一次，我少走了很多彎路，也少花了很多 Token。

想問問你：上一次 AI 做出來跟你想的差很多，是哪個細節你沒講？

### Instagram

你的提示詞很完整，但你的需求不完整。

這是兩件事。有些東西你知道，卻不知道要講；有些東西你根本不知道自己不知道。

所以我做了一個技能，讓 AI 在動工前先訪談我，問到我自己都沒想到的地方，
再產出一頁需求規格卡。

一句話的想法，變成一份完整規格書。專案就不會做到一半才發現要重來。

AI Agent 基本功系列到這一集收尾，這是最後一塊拼圖。

你做專案時最常漏掉的是哪一種細節？留言聊聊。

### Threads

提示詞完整，不等於需求完整。

你講得出來的只有兩個象限，真正會出事的是你講不出口的那兩個。
動工前先讓 Agent 問你三輪，比做完再改便宜太多了。
